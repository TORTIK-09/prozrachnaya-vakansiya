# Прозрачная вакансия — КАНТКОД (Онлайн-отбор • Регион 39)

Прототип сервиса автоматического аудита понятности условий работы в вакансиях Калининградской области (регион `39`) с портала **«Работа в России»** (`trudvsem.ru`), дополненный сценарием **ИИ-адаптации черновика резюме соискателя под выбранную вакансию**.

Сервис помогает редактору центра занятости / портала подготовить конкретные, нейтральные и адресные уточнения для работодателя без ручного копирования текста, без вымышленных фактов и без юридических обвинений.

---

## Точка входа и архитектура

Обработка данных начинается с файла **[`main.py`](main.py)** (единый CLI-интерфейс), который вызывает оркестратор **[`src/analyzer.py`](src/analyzer.py)**.

Конвейер обработки каждой вакансии состоит из 4 этапов:
1. **Получение и дедупликация данных ([`src/api_client.py`](src/api_client.py))**:
   - В **рабочем режиме (`live` / `schedule`)**: загрузка вакансий региона 39 по HTTP с API `http://opendata.trudvsem.ru/api/v1/vacancies/region/39` с автоматической пагинацией (**обрабатывает минимум 2 страницы**, если лимит и объём данных позволяют) и дедупликацией по `id`.
   - В **проверочном режиме (`verify`)**: чтение локального JSON-файла в формате ответов API без сетевых обращений к порталу.
2. **Структурный и кросс-полевой анализ ([`src/rule_engine.py`](src/rule_engine.py))**:
   - Оценка 7 ключевых аспектов вакансии: **Название должности**, **Обязанности**, **Требования**, **Оплата**, **График**, **Место работы**, **Тип занятости**.
   - Сопоставление структурированных полей API (`salary_min`, `salary_max`, `requirement.experience`, `requirement.education`, `schedule`, `addresses.address[].location`) с текстовыми описаниями (`duty`, `requirement.qualification`, `requirements`). Если конкретные сведения уже есть в структурированном поле, отсутствие их дублирования в тексте не считается ошибкой.
3. **ИИ-обработка ([`src/ai_engine.py`](src/ai_engine.py))**:
   - **Шаг, на котором используется ИИ**: после первичной структурной проверки карточка вакансии и найденные маркеры передаются в ИИ-модуль (`AIEngine.enrich_and_validate_issues`). Модель выполняет семантический анализ текста на скрытые неоднозначности и противоречия, определяет предметную область должности и формирует контекстные рекомендации (`recommendation`) для редактора с конкретными примерами уточнений под профиль вакансии.
4. **Сохранение отчёта и защита от сбоев ([`src/report_manager.py`](src/report_manager.py))**:
   - Контроль идемпотентности по `id` и SHA-256 хэшу (`content_hash`): повторный запуск на неизменных данных сохраняет ровно **один результат на ID вакансии** в текущем отчёте.
   - При недоступности API сервис выводит сообщение об ошибке и сохраняет **последний успешный отчёт** (`reports/latest_report.json` и резервную копию `reports/last_successful_report.json`).

## Зависимости и установка

Требуется **Python 3.10+**.

```bash
pip install -r requirements.txt
```

Основные зависимости ([`requirements.txt`](requirements.txt)): `requests`, `pydantic`, `python-dotenv`, `fastapi`, `uvicorn`, `python-multipart`, `jinja2`.

## Настройки

Все параметры настраиваются через переменные окружения (шаблон в **[`.env.example`](.env.example)**) или аргументы командной строки. Секретные ключи хранятся вне репозитория (`.env` добавлен в [`.gitignore`](.gitignore)). Сервис полностью работоспособен «из коробки» даже без создания `.env`.

| Параметр | Значение по умолчанию | Описание |
| :--- | :--- | :--- |
| `API_URL` | `http://opendata.trudvsem.ru/api/v1/vacancies/region/39` | URL источника данных API «Работа в России» для региона 39 |
| `MAX_VACANCIES` | `20` | Максимальное число обрабатываемых вакансий за запуск |
| `PAGE_LIMIT` | `10` | Число вакансий на одной странице пагинации (при `MAX_VACANCIES=20` и `PAGE_LIMIT=10` загружается минимум 2 страницы) |
| `SCHEDULE_INTERVAL_MINUTES` | `60` | Интервал автоматического запуска по расписанию (в минутах) |
| `SCHEDULE_CRON` | `0 * * * *` | Cron-выражение расписания |
| `AI_PROVIDER` | `auto` | Режим ИИ: `auto`, `ollama`, `openrouter`, `gemini`, `openai`, `local_ai` |
| `OLLAMA_MODEL` | `qwen2.5:3b` | Локальная модель Ollama для запуска без ключей и аккаунта |

## Как жюри запустить проверочный режим с ИИ без покупки аккаунта

В проекте предусмотрены **три бесплатных способа** запуска ИИ-обработки без покупки платных аккаунтов:

### Вариант 1. Мгновенный автономный запуск «из коробки» (режим `auto` / `local_ai`)
Не требует регистрации, API-ключей или установки внешних серверов. Используется встроенный локальный семантический ИИ-анализатор (`LocalSemanticAI-RU-v1` в [`src/ai_engine.py`](src/ai_engine.py)):
```bash
python main.py verify --input kantkod_sample_vacancies.json --output reports/sample_report.json
```
Для проверки на **отдельном закрытом наборе жюри**:
```bash
python main.py verify --input путь_к_файлу_жюри.json --output reports/jury_report.json
```

### Вариант 2. Локальная LLM через Ollama (бесплатно, без аккаунта)
Если на машине установлена [Ollama](https://ollama.com):
```bash
ollama pull qwen2.5:3b
python main.py --ai-provider ollama verify --input kantkod_sample_vacancies.json --output reports/sample_report.json
```

### Вариант 3. Бесплатные облачные модели OpenRouter (`:free`) или Google Gemini Free Tier
При желании можно указать бесплатный ключ в `.env` (`OPENROUTER_API_KEY` с моделью `google/gemma-3-27b-it:free` или `GEMINI_API_KEY` с `gemini-2.5-flash`) и запустить:
```bash
python main.py --ai-provider openrouter verify --input kantkod_sample_vacancies.json
```

## Команды запуска и проверок

### 1. Проверочный режим (локальный JSON без обращения к порталу)
```bash
python main.py verify --input kantkod_sample_vacancies.json --output reports/sample_report.json
```
Готовый пример отчёта на учебных данных сохранён в **[`reports/sample_report.json`](reports/sample_report.json)**.

### 2. Рабочий режим (ручной запуск загрузки из API региона 39)
```bash
python main.py live --url http://opendata.trudvsem.ru/api/v1/vacancies/region/39 --max-vacancies 20 --page-limit 10 --output reports/latest_report.json
```

### 3. Рабочий режим по расписанию (автоматизация)
Встроенный планировщик ([`src/scheduler.py`](src/scheduler.py)):
```bash
python main.py schedule --interval-minutes 60
```
Дополнительные конфигурации расписания размещены в папке **[`automation/`](automation/)**:
- [`automation/schedule_config.json`](automation/schedule_config.json) — конфигурация параметров расписания и отказоустойчивости;
- [`automation/cron_schedule.conf`](automation/cron_schedule.conf) — расписание для `cron` (Linux);
- [`automation/windows_task_scheduler.ps1`](automation/windows_task_scheduler.ps1) — регистрация задачи в Планировщике заданий Windows;
- [`automation/n8n_workflow.json`](automation/n8n_workflow.json) — импортируемый JSON workflow для **n8n** (версия `1.72+`).

### 4. Дополнительный сценарий (ИИ-адаптация черновика резюме под вакансию)
```bash
python main.py resume --resume-id RES-39-03 --vacancy-id DEMO-39-003 --output data/sample_resume_draft_output.json
```

### 5. Интерактивный веб-интерфейс (для демонстрации и проверки)
```bash
python main.py web --host 127.0.0.1 --port 8085
```
После запуска откройте `http://127.0.0.1:8085` в браузере.

### 6. Автотесты
Проверяют учебный набор, пагинацию (`>= 2` страниц), отсутствие дубликатов при повторном запуске, сохранение последнего успешного отчёта при отказе API и дополнительный сценарий:
```bash
python -m unittest discover -s tests -v
```

## Формат отчёта

Отчёт сохраняется в JSON (см. пример **[`reports/sample_report.json`](reports/sample_report.json)**).

### Корневой объект отчёта (`FullReport`)
- `generated_at` *(string)* — дата и время генерации отчёта в формате ISO 8601.
- `mode` *(string)* — режим: `"verify"` (локальный JSON) или `"live"` (API).
- `source` *(string)* — путь к входному файлу или URL API.
- `ai_provider_used` *(string)* — использованный ИИ-провайдер и модель.
- `pages_processed` *(int)* — количество обработанных страниц источника.
- `total_vacancies` *(int)* — общее число уникальных вакансий в отчёте.
- `clean_vacancies` *(int)* — число прозрачных вакансий без замечаний.
- `vacancies_with_issues` *(int)* — число вакансий с замечаниями.
- `total_issues` *(int)* — общее количество найденных замечаний.
- `vacancies` *(array)* — массив объектов проверки по каждой входной вакансии (строго 1 объект на 1 ID вакансии).

### Объект вакансии в массиве `vacancies` (`VacancyReportItem`)
- `id` *(string)* — уникальный ID вакансии из поля `vacancy.id` (например, `"DEMO-39-001"`).
- `url` *(string | null)* — ссылка на карточку вакансии (`vac_url` из API) при наличии, иначе `null`.
- `job_name` *(string)* — название должности (`job-name`).
- `company_name` *(string)* — название работодателя (`company.name`).
- `location` *(string)* — основной адрес из карточки (`addresses.address[0].location`).
- `is_transparent` *(bool)* — `true`, если замечаний нет (`issues` пуст), иначе `false`.
- `transparency_score` *(int)* — оценка прозрачности описания условий от `0` до `100`.
- `content_hash` *(string)* — SHA-256 хэш данных вакансии для идемпотентности при повторных запусках.
- `issues` *(array)* — массив замечаний. Если замечаний нет — пустой массив `[]`.

### Объект замечания в массиве `issues` (`VacancyIssue`)
- `type` *(string)* — тип проблемы: `"пропуск"`, `"неоднозначность"` или `"противоречие"`.
- `topic` *(string)* — тема проверки: `"Название должности"`, `"Обязанности"`, `"Требования"`, `"Оплата"`, `"График"`, `"Место работы"`, `"Тип занятости"`.
- `field` *(string)* — поле (или поля) источника в исходном JSON вакансии.
- `quote` *(string)* — цитата или значение из поля источника:
  - для **`"пропуск"`** — строго пустая строка `""`;
  - для **`"неоднозначность"`** — точная цитата или значение из поля;
  - для **`"противоречие"`** — **оба исходных конфликтующих значения** с указанием полей.
- `issue` *(string)* — суть проблемы (почему это мешает соискателю понять условия или каких сведений не хватает).
- `recommendation` *(string)* — конкретная рекомендация для редактора/работодателя (что именно уточнить, без вымышленных фактов и выводов о нарушении закона).
- `detected_by` *(string)* — маркер детектора (`"rules+ai"`, `"ai"`, `"rules"`).

## Дополнительный сценарий: ИИ-адаптация черновика резюме под вакансию региона 39

Реализован в модуле **[`src/resume_adapter.py`](src/resume_adapter.py)**, обезличенные резюме находятся в **[`data/sample_resumes.json`](data/sample_resumes.json)**, пример результата — в **[`data/sample_resume_draft_output.json`](data/sample_resume_draft_output.json)**.

1. **Кому помогает сценарий**:
   - Соискателям Калининградской области и карьерным консультантам центров занятости, которым нужно быстро адаптировать черновик резюме под конкретную вакансию государственных, муниципальных или региональных организаций и подготовить список вопросов работодателю перед собеседованием.
2. **Какие данные API использует**:
   - Из карточки вакансии региона 39 используются поля: `id`, `job-name`, `company.name`, `duty`, `requirement.education`, `requirement.experience`, `requirement.qualification`, `requirements`, `employment`, `schedule`, `addresses.address[].location`, а также массив найденных замечаний из базового анализатора прозрачности.
3. **Какой результат выдаёт**:
   - Оценку совместимости кандидата с вакансией (`match_score`, `matched_skills`, `missing_or_unconfirmed_requirements`);
   - Структурированный черновик резюме (`tailored_resume_draft`), где **опыт, навыки и образование берутся строго из исходного резюме соискателя** (без выдумывания стажа или дипломов) и ранжируются по релевантности задачам вакансии;
   - Черновик сопроводительного письма (`cover_letter_draft`);
   - Список конкретных вопросов работодателю (`questions_for_employer`), автоматически сформированный по найденным в вакансии неоднозначностям и пропускам.

- **Участник 3 (Frontend / QA & Документация)**: разработка интерактивного веб-интерфейса (`src/web_app.py`), автотестов (`tests/test_analyzer.py`), подготовка `README.md` и демонстрационного видео.
