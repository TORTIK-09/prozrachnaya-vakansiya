## 1. Что делает сервис

Сервис получает вакансии Калининградской области с портала «Работа в России» и по каждой составляет список замечаний трёх видов:

| Вид | Что значит | Пример |
|---|---|---|
| Пропуск (`missing`) | нужных сведений нет | не указана зарплата |
| Неоднозначность (`ambiguous`) | сведения есть, но понять их можно по-разному | «гибкий график» без часов |
| Противоречие (`contradiction`) | два места вакансии говорят разное | «дистанционно» и «ежедневно в офисе» |

Замечания относятся к семи темам: название должности, обязанности, требования, оплата, график, место работы, тип занятости. К каждому приложены дословная цитата из вакансии и рекомендация — что уточнить у работодателя.

Вакансию проверяют двое:

- **Системный AI** — встроенный алгоритм на правилах. Это не нейросеть: правила написаны вручную, а нормы опыта по должностям посчитаны по вакансиям портала. Работает мгновенно и без сети.
- **ИИ** — языковая модель, локальная или облачная. Разбирает вакансию независимо от правил.

## 2. Установка

### Что нужно

- **uv** — менеджер пакетов и окружений Python. Python 3.12 он скачает сам.
- **git** — чтобы получить проект.
- **Ollama** — по желанию, для локальной модели. Без неё сервис работает на одном Системном AI.

### Установка uv

```
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# macOS и Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# либо через pip
pip install uv
```

Откройте новое окно терминала и проверьте: `uv --version`.

### Установка проекта

```
git clone https://github.com/TORTIK-09/prozrachnaya-vakansiya.git
cd prozrachnaya-vakansiya
uv sync
```

`uv sync` создаёт окружение в папке `.venv` и ставит зависимости. Все команды ниже запускаются из папки проекта.

### Локальная модель (по желанию)

1. Установить Ollama с https://ollama.com.
2. Скачать модель: `ollama pull qwen2.5:3b` (около 2 ГБ).
3. Больше ничего: сервис находит запущенную Ollama сам. Для `qwen2.5:3b` профиль калибровки поставляется с проектом.

## 3. Команды

Общий вид: `uv run python -m pv [--config путь] команда [параметры]`.

| Команда | Что делает |
|---|---|
| `check ФАЙЛ` | Проверочный режим: отчёт по локальному JSON. К порталу не обращается. |
| `run` | Рабочий режим: загрузить вакансии из API и записать отчёт. |
| `schedule` | Работать постоянно и запускать рабочий режим по расписанию. |
| `web` | Запустить панель. |
| `calibrate` | Откалибровать подключённую модель и сравнить её с Системным AI. |
| `learn` | Пересчитать нормы опыта по должностям на вакансиях портала. |
| `forget` | Удалить накопленное на этом компьютере: профили моделей, нормы, кэш. |
| `resume` | Дополнительный сценарий: черновик резюме под вакансию из отчёта. |

Параметры:

| Команда | Параметр | Значение |
|---|---|---|
| `check` | `--out ПУТЬ` | куда записать отчёт; по умолчанию `reports/check.json` |
| `check` | `--cache` | не анализировать заново неизменившиеся вакансии |
| `run` | `--max ЧИСЛО` | максимум вакансий |
| `run` | `--url АДРЕС` | другой адрес источника |
| `web` | `--port ЧИСЛО` | порт панели; по умолчанию 8085 |
| `learn` | `--count ЧИСЛО` | сколько вакансий взять; по умолчанию 400 |
| `resume` | `--vacancy ID` | ID вакансии из отчёта (обязательно) |
| `resume` | `--resume ID` | ID резюме из `examples/sample_resumes.json`; по умолчанию `RES-01` |
| `resume` | `--report ПУТЬ` | отчёт, из которого берётся вакансия |
| `resume` | `--out ПУТЬ` | куда записать черновик; иначе — на экран |
| `check`, `run`, `schedule`, `web` | `--no-llm` | не обращаться к модели |

Коды возврата: `0` — успешно, `2` — ошибка (нет файла, неверные настройки, источник недоступен или пуст).

Примеры:

```
uv run python -m pv check examples/sample_vacancies.json --out reports/check.json
uv run python -m pv check мой_набор.json --no-llm
uv run python -m pv run --max 50
uv run python -m pv web --port 8090
uv run python -m pv resume --resume RES-03 --vacancy DEMO-39-003 --report reports/check.json
```

## 4. Настройки

Настройки собираются из четырёх источников; каждый следующий перекрывает предыдущий:

1. значения по умолчанию;
2. файл `config.toml` в корне проекта (образец — `config.example.toml`);
3. файл `.env` и переменные окружения с приставкой `PV_`;
4. параметры команды (`--max`, `--url`, `--port`).

| Настройка | Переменная | По умолчанию | Что значит |
|---|---|---|---|
| `source_url` | `PV_SOURCE_URL` | адрес API региона 39 | источник вакансий |
| `schedule` | `PV_SCHEDULE` | `0 6 * * *` | расписание в формате cron |
| `max_vacancies` | `PV_MAX_VACANCIES` | `200` | сколько вакансий загружать |
| `page_size` | `PV_PAGE_SIZE` | `100` | размер страницы; больше 100 API не отдаёт |
| `timeout` | `PV_TIMEOUT` | `60` | секунд на один запрос к API |
| `retries` | `PV_RETRIES` | `3` | попыток на страницу |
| `workers` | `PV_WORKERS` | `4` | потоков анализа; с локальной моделью всегда 1 |
| `reports_dir` | `PV_REPORTS_DIR` | `reports` | папка отчётов и состояния |
| `llm_base_url` | `PV_LLM_BASE_URL` | пусто | адрес сервера модели |
| `llm_model` | `PV_LLM_MODEL` | пусто | имя модели |
| `llm_api_key` | `PV_LLM_API_KEY` | пусто | ключ; для локальной модели не нужен |
| `web_host` | `PV_WEB_HOST` | `127.0.0.1` | адрес, на котором слушает панель |
| `web_port` | `PV_WEB_PORT` | `8085` | порт панели |
| `calib_minutes` | `PV_CALIB_MINUTES` | `0` | минут на калибровку; 0 — сервис выбирает сам |

Неизвестная настройка в `config.toml` — ошибка с понятным сообщением. Ключи в `config.toml` не пишите: для них есть `.env` (образец — `.env.example`); оба файла в репозиторий не попадают.

Модель и режим можно выбрать и в панели, в окне «Настройки ИИ». Если модель задана переменными `PV_LLM_BASE_URL` или `PV_LLM_MODEL`, они главнее выбора в панели.

## 5. Как обрабатывается вакансия

```
источник (API или файл) → нормализация → анализ → отчёт
   pv/source.py            pv/normalize.py  pv/analyze/  pv/report.py
```

1. **Источник.** Из API вакансии берутся постранично до заданного лимита, с повторами при сбое и защитой от дублей. Из файла принимаются три формата: ответ API, список страниц, список вакансий.
2. **Нормализация.** Текст очищается от HTML и лишних пробелов, числа приводятся к числам. Контактные данные — телефоны, почта, контактные лица — отбрасываются и дальше не идут.
3. **Системный AI** (`pv/analyze/rules.py`) проверяет вакансию по семи темам.
4. **ИИ** (`pv/analyze/ai.py`) получает поля вакансии и методику проверки и возвращает свои замечания. Каждая цитата модели сверяется с текстом вакансии: если её там нет дословно, замечание отбрасывается.
5. **Объединение** (`pv/analyze/__init__.py`). Если проблему видят оба, замечание одно: формулировка от ИИ, цитаты от Системного AI, `source: both`. Замечания ИИ, которых нет у Системного AI, добавляются, если этот вид замечаний прошёл калибровку. Пропуски от ИИ не берутся: модель склонна считать пропуском то, что указано в другом поле.
6. **Отчёт.** Одна запись на ID вакансии в порядке входных данных; замечания, не прошедшие проверку контракта, отбрасываются и считаются в `stats`.

Если модель недоступна или ответила мусором, по этой вакансии остаются замечания Системного AI — сервис не падает.

### Нормы опыта

Опыт «0» в поле значит либо «опыт не нужен», либо «поле забыли заполнить». Системный AI различает это по тексту вакансии, по названию должности и по нормам: в какой доле вакансий той же профессии на портале опыт требуется. Нормы поставляются с проектом (`pv/data/experience_norms.json`, 400 вакансий) и пересчитываются командой `learn`; местный пересчёт хранится в `reports/experience_norms.json` и главнее поставляемого.

## 6. Языковая модель

Подходит любая модель с OpenAI-совместимым протоколом (`/chat/completions`).

### Пять режимов

| Режим | Имя в настройках | Что в отчёте |
|---|---|---|
| Только Системный AI | `rules_only` | замечания правил; модель не используется |
| Системный AI + локальная ИИ | `local` | объединённые замечания |
| Только локальная ИИ | `local_only` | только замечания модели |
| Системный AI + ИИ по API | `custom_api` | объединённые замечания |
| Только ИИ по API | `custom_api_only` | только замечания модели |

В режимах «только ИИ» Системный AI не работает и профиль калибровки к отчёту не применяется: человек сознательно выбрал отчёт одной модели. Цитаты модели проверяются по тексту и в этих режимах.

### Как сервис находит модель

1. настройки из переменных окружения или `config.toml`;
2. выбор, сохранённый в окне «Настройки ИИ»;
3. локальная Ollama на `http://127.0.0.1:11434`, если она запущена.

### Сила модели

Сервис относит модель к одному из трёх классов — небольшая, средняя, сильная — по данным Ollama, по имени или по справочнику; неизвестная модель считается небольшой. От класса зависит, сколько примеров с замечаниями модель получает в запросе: небольшая — ни одного (она их копирует), средняя — один, сильная — два.

### Облачные провайдеры

В окне настроек есть список из 22 провайдеров с адресами: 5 локальных серверов и 17 облачных API. Ключ вводит пользователь; сервис хранит его только на этом компьютере. Режимы с облачной моделью используют тот же клиент, что и локальные, но с настоящим платным ключом мы их не проверяли.

## 7. Калибровка

Калибровка — не обучение: веса модели не меняются. Сервис выясняет, каким видам замечаний этой модели можно верить.

**Как идёт.** Модель получает размеченные вакансии по одной и не видит ответов. Вакансии берутся по очереди из трёх наборов (всего 32), поэтому даже короткая калибровка видит и понятные, и проблемные. Скорость измеряется на первых двух вакансиях; дальше берётся столько, сколько помещается в отведённое время.

**Что решается.** Для каждого вида замечаний («тема + вид») считается, сколько раз модель оказалась права и сколько ошиблась. Вид остаётся в отчёте, если подтвердился не меньше двух раз и точность не ниже 75 %. Остальные отключаются.

**Шаблонные ответы.** Если больше половины замечаний модели — одного вида и она выдаёт их даже на понятные вакансии, это отмечается в статистике.

**Где хранится.** Профиль модели — `reports/profiles/<провайдер>__<модель>.json`. Профиль для `qwen2.5:3b` поставляется в `pv/profiles/`. Профиль привязан к версии методики: после её изменения модель калибруется заново.

**Пока модель не откалибрована**, её замечания в отчёт не идут — отчёт собирается по Системному AI.

**Запуск.** В панели — автоматически при первом подключении модели и кнопкой «Перекалибровать ИИ» в настройках. Из командной строки — `uv run python -m pv calibrate`.

**Системный AI в это время** обновляет нормы опыта на вакансиях портала.

**Сколько времени.** Зависит от модели и компьютера. На нашем ноутбуке без подходящей видеокарты `qwen2.5:3b` тратит около двух минут на вакансию; на компьютере с видеокартой или с облачной моделью — секунды.

## 8. Панель

Запуск: `uv run python -m pv web`, адрес http://127.0.0.1:8085.

| Раздел | Что в нём |
|---|---|
| Окно «Настройки ИИ» | Режим, время на калибровку, провайдер, адрес, модель, ключ. Открывается само при первом запуске, дальше — кнопкой. |
| Отчёт: сводка | Всего вакансий, понятных, требующих уточнения, всего замечаний; разбивка по темам. |
| Отчёт: список | Вакансии с фильтрами по виду замечаний. |
| Отчёт: разбор вакансии | Замечания и текст вакансии рядом; цитаты подсвечены в полях. |
| Проверочный набор | Учебные вакансии; сохранённый отчёт по ним восстанавливается мгновенно. |
| Вакансии с портала | Загрузка заданного числа вакансий из API — тот же код, что по расписанию. |
| Загрузка своего JSON | Файл до 20 МБ в формате ответа API. |
| Экспорт JSON | Текущий отчёт файлом. |
| Резюме под вакансию | Дополнительный сценарий. |
| Статистика | Показатели режимов на размеченных наборах. |
| Как это работает | Краткое объяснение шагов проверки. |

**Проверка в реальном времени.** Вакансии появляются в списке по мере разбора, числа в сводке меняются плавно. Вакансия показывается после того, как её обработали и Системный AI, и ИИ. Локальной модели вакансии отправляются по одной, поэтому строки появляются последовательно.

**Кто видит проблему.** У замечания метки «Системный AI» и «ИИ». Если ответы разошлись, в блоке «Выбор за вами» можно принять один из них: статус замечания меняется на принятый ответ, решение сохраняется с историей — что было, что стало, когда.

**Калибровка.** Пока она идёт, вверху висит уведомление с ходом и оценкой времени; итог остаётся, пока его не закроют.

## 10. Форматы данных

**Вход** — JSON в формате ответа API портала: `results.vacancies[].vacancy`. Принимаются также список таких ответов (страниц) и простой список вакансий. Образец — `examples/sample_vacancies.json`.

**Отчёт** — описан в [README](../README.md#формат-отчёта); образец — `examples/sample_report.json`. Коротко: `generated_at`, `mode` (`api` или `file`), `source`, `model`, `stats`, `vacancies[]`; у вакансии — `id`, `url`, `title`, `company`, `findings[]`, `fields`.

**Контракт замечания** проверяется кодом (`pv/models.py`): тема и вид — из закрытых списков; цитата дословно присутствует в названном поле; у пропуска цитата пустая; у противоречия есть второе значение `conflict_with`. Замечание, не прошедшее проверку, в отчёт не попадает.

**Резюме** — `examples/sample_resumes.json`; черновик — `examples/sample_resume_draft.json`.

## 11. Запросы к серверу панели

Сервер отвечает только на запросы с этого компьютера. Страницы описания API (`/docs`) отключены намеренно.

| Запрос | Что делает |
|---|---|
| `GET /api/status` | источник, расписание, модель, режим, состояние калибровки, последняя ошибка |
| `GET /api/settings` | режимы, провайдеры, локальные модели, характеристики компьютера, сохранённый выбор (ключ не отдаётся) |
| `POST /api/settings` | сохранить режим и модель: `mode_type`, `provider`, `base_url`, `model`, `api_key`, `calib_minutes` |
| `GET /api/plan` | план калибровки для модели: `model`, `mode_type`, `base_url`, `minutes` |
| `GET /api/calibration` | ход и итог калибровки |
| `POST /api/calibration` | запустить калибровку заново |
| `GET /api/stats` | показатели режимов, число решений человека |
| `GET /api/report?kind=check\|latest` | отчёт вместе с решениями человека |
| `POST /api/check-sample` | проверить учебный набор; `restore=1` — вернуть сохранённый отчёт; `background=1` — в фоне |
| `POST /api/check` | проверить JSON из тела запроса; `name`, `background` |
| `POST /api/run` | рабочий режим вручную; `max_vacancies` от 1 до 5000, `background` |
| `GET /api/progress?since=N` | ход текущей проверки и готовые записи после номера N |
| `POST /api/verdict` | решение по расхождению: `vacancy_id`, `topic`, `kind`, `choice` = `rule`, `llm` или `none` |
| `GET /api/resumes` | учебные резюме |
| `POST /api/resume` | черновик резюме: `resume_id`, `vacancy_id`, `kind` |

Одновременно идёт одна проверка; второй запуск получает ответ 409.

## 12. Расписание

Три равноценных способа, все запускают `python -m pv run`:

| Способ | Как включить |
|---|---|
| Встроенный планировщик | `uv run python -m pv schedule`; выражение — в настройке `schedule` |
| GitHub Actions | `.github/workflows/schedule.yml` — по расписанию и кнопкой «Run workflow» |
| Планировщик ОС | Windows — `automation/windows_task.ps1`; Linux и macOS — `automation/crontab.example` |

Формат выражения: `минута час день_месяца месяц день_недели`; поддерживаются `*`, списки, диапазоны и шаг (`*/15`).

Повторный запуск на тех же данных даёт тот же отчёт. При недоступном портале последний успешный отчёт не затрагивается.

## 13. Проверка качества

```
uv run pytest                                   # 130 тестов, без сети и без настоящей модели
uv run python eval/score.py reports/check.json  # сравнение отчёта с разметкой
```

| Набор | Файлы | Что проверяет |
|---|---|---|
| Учебный | `examples/sample_vacancies.json`, `eval/gold.json` | 10 вакансий организаторов, наша разметка |
| Смысловые расхождения | `eval/extra_vacancies.json`, `eval/extra_gold.json` | 12 вакансий, где проблема выражена смыслом |
| Контрольный | `eval/holdout_vacancies.json`, `eval/holdout_gold.json` | 10 вакансий в других формулировках |
| Живые данные | `eval/real_sample.json`, `eval/review.md` | 100 вакансий портала без контактов; ручной просмотр 30 из них |

В разметке у вакансии два списка: обязательные замечания и допустимые. Найденное сверх обоих считается лишним. Скрипт оценки проходит, если полнота не ниже 0,9 и лишних не больше одного на десять вакансий.

## 14. Безопасность и данные

- **Панель доступна только с этого компьютера.** Она слушает `127.0.0.1` и отклоняет запросы с другим заголовком Host — это защищает от подмены адреса через DNS.
- **Запросы с чужих сайтов отклоняются:** у изменяющих запросов проверяется заголовок Origin.
- **Заголовки защиты:** политика содержимого страницы, запрет встраивания во фрейм, запрет угадывания типа содержимого.
- **Текст вакансий вставляется на страницу как текст**, а не как разметка: код из вакансии в браузере не выполнится.
- **Загрузка файла** ограничена 20 МБ; пути к файлам в запросах не принимаются.
- **Текст вакансии передаётся модели как данные**, отдельно от инструкции; ответ модели проверяется по тексту вакансии.
- **Контактные данные** из вакансий отбрасываются при нормализации: в модель и в отчёт они не попадают.
- **Ключи.** Ключ из `.env` в репозиторий не попадает. Ключ, введённый в панели, хранится на этом компьютере в `reports/model_settings.json` открытым текстом и обратно в браузер не отдаётся. Если компьютером пользуются другие люди, задавайте ключ через `.env`.
- **Облачная модель** получает тексты вакансий без контактов. Локальная модель ничего наружу не передаёт.

Панель не рассчитана на публикацию в интернете: в ней нет входа по паролю. Не меняйте `web_host` на внешний адрес.

## 15. Частые вопросы и неполадки

**`uv` не найден после установки.** Откройте новое окно терминала: путь обновляется только в новых окнах.

**Порт 8085 занят.** `uv run python -m pv web --port 8090`.

**Панель пишет, что модель не подключена.** Запущена ли Ollama (значок в трее или `ollama list`)? Скачана ли модель (`ollama pull qwen2.5:3b`)? Панель проверяет подключение заново раз в 30 секунд.

**Проверка с моделью идёт очень долго.** На компьютере без подходящей видеокарты небольшая модель тратит минуты на вакансию. Варианты: режим «Только Системный AI», меньше вакансий, облачная модель, флаг `--no-llm`.

**Модель подключена, а её замечаний в отчёте нет.** Либо она ещё не откалибрована, либо калибровка отключила все виды её замечаний: так бывает с небольшими моделями, которые отвечают шаблонно. Смотрите страницу «Статистика».

**Модель перестала отвечать.** Перезапустите Ollama. Сервис в это время продолжает работать на Системном AI.

**Портал не отвечает.** Рабочий режим завершится с кодом 2, запишет `reports/last_error.json` и сохранит прежний отчёт. Проверочный режим от портала не зависит.

**В русских словах консоли вместо букв значки (Windows).** Выполните `chcp 65001` или задайте переменную `PYTHONUTF8=1`. На содержимое отчётов это не влияет: они всегда в UTF-8.

**Как начать с чистого листа.** `uv run python -m pv forget`, а чтобы сбросить и выбор в панели — удалите папку `reports`.

## 16. Известные ограничения

- Разметка всех наборов наша; эталон жюри нам неизвестен.
- Небольшая локальная модель (`qwen2.5:3b`) после калибровки почти ничего не добавляет к Системному AI: её собственные виды замечаний отключаются как ненадёжные. Совпадающие замечания она переформулирует.
- Режимы с облачной моделью с настоящим ключом не проверялись.
- Оценка времени калибровки до её начала на медленных компьютерах занижена; после первых двух вакансий она уточняется.
- Решения человека по расхождениям сохраняются и показываются, но на отчёт и профиль модели пока не влияют (см. раздел README «Что хотели реализовать дальше»).
- Нормы опыта группируют должности по началу названия; редкие профессии в них не попадают.
