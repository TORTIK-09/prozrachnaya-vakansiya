# Задание в виде списка требований

Краткий пересказ тестового задания «Прозрачная вакансия» (онлайн-отбор КАНТКОД). Оригинал организаторов — у владельца репозитория. Каждое требование помечено номером части, которая за него отвечает.

## Что делает сервис

Получает вакансии Калининградской области с портала «Работа в России» и формирует отчёт о том, насколько понятно описаны условия работы. Отчёт читает редактор вакансии, чтобы подготовить уточнения для работодателя.

## Обязательное

| № | Требование | Часть |
|---|---|---|
| 1 | Источник — API региона 39: `http://opendata.trudvsem.ru/api/v1/vacancies/region/39` | 1 |
| 2 | Рабочий режим: загрузка, обработка и сохранение отчёта по расписанию, без ручного копирования | 1 |
| 3 | Ручной запуск того же процесса | 1 |
| 4 | Настраиваются URL источника, расписание, максимальное число вакансий | 1 |
| 5 | Проверочный режим: тот же анализатор на локальном JSON в формате ответа API, без обращения к порталу; отчёт по всем переданным вакансиям | 1 |
| 6 | Обработать не меньше двух страниц, если позволяют лимит и объём данных | 1 |
| 7 | Повторный запуск на тех же данных — один результат на ID вакансии в текущем отчёте | 1 |
| 8 | API недоступен — сообщить об ошибке и сохранить последний успешный отчёт | 1 |
| 9 | Оценить: название должности, обязанности, требования, оплату, график, место работы, тип занятости | 2 |
| 10 | Учитывать и описание, и структурированные поля; сведения в поле не обязаны повторяться в описании | 2 |
| 11 | Отмечать пропуски, неоднозначности и противоречия, мешающие понять условия | 2 |
| 12 | Рекомендация говорит, что именно уточнить; без вымышленных фактов и выводов о нарушении закона | 2 |
| 13 | Отчёт в JSON: на каждую вакансию — ID, ссылка при наличии, массив замечаний (пустой, если их нет) | 1 |
| 14 | В замечании: тема, поле источника, цитата или значение, суть проблемы, рекомендация | 2 |
| 15 | Пропуск: поле указано, цитата пустая, объяснено, чего не хватает. Противоречие: оба исходных значения | 2 |
| 16 | ИИ выполняет часть обработки, влияющую на отчёт | 2 |
| 17 | Жюри может запустить проверочный режим с ИИ без покупки аккаунта | 2, 5 |
| 18 | Ключи хранятся вне репозитория | все |

## Необязательное

| Требование | Часть |
|---|---|
| Свой сценарий на данных API региона 39 (пример из задания — черновик резюме под вакансию по резюме соискателя); резюме только вымышленные или обезличенные; опыт, навыки и образование берутся из исходного резюме | 4 |
| Интерфейс, публичный деплой | 4 |

## Что сдаётся

| Материал | Часть |
|---|---|
| Публичный репозиторий и SHA коммита | 5 |
| В репозитории: исходники, конфигурация автоматизации, README, пример отчёта на учебных данных | 1, 5 |
| README: зависимости, настройки, команды запуска и проверок, формат отчёта, вклад участников; модель, провайдер или способ локального запуска; шаг, на котором используется ИИ; файл, с которого начинается обработка | 5 |
| Если есть свой сценарий — в README: кому помогает, какие данные API использует, какой результат выдаёт | 4, 5 |
| Видео до 3 минут: как получаются данные, где применяется ИИ, какой результат; открывается без запроса доступа | 5 |

## Как оценивают

Критерии в задании не названы. Известно, что жюри прогоняет проверочный режим на собственном закрытом наборе. В учебном наборе четыре вакансии из десяти — понятные, без замечаний; значит, лишние замечания почти наверняка считаются ошибкой наравне с пропущенными.
