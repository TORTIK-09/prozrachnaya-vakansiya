# Часть 5. README, видео, сдача

Сначала прочитайте `00-contract.md` и `docs/task.md`.

## Цель

Жюри должно за десять минут понять, что сделано, и запустить проверочный режим у себя с первого раза. Работа, которую не смогли запустить, не оценивается, какой бы хорошей она ни была.

## Вопросы на старте — решить в первый час и написать в общий чат

1. **Точный час сдачи 25.11 и куда отправлять** репозиторий, SHA и видео — узнать у владельца репозитория.
2. **Где лежит видео.** Оно должно открываться без запроса доступа: проверьте ссылку в окне браузера без входа в аккаунт.
3. **На чём проверяем запуск «с нуля».** Нужен компьютер или виртуальная машина, где проект ни разу не запускался.

## README — обязательные разделы

Список взят из задания; ничего не пропускать.

1. **Что это** — два-три предложения.
2. **Быстрый запуск проверочного режима** — в самом верху, копируемыми командами: установка, запуск модели, одна команда проверки, где лежит результат. Именно это жюри сделает первым.
3. **Модель** — какая, какой провайдер или способ локального запуска, как запустить без покупки аккаунта. Текст даёт часть 2.
4. **Где применяется ИИ** — на каком шаге и как влияет на отчёт.
5. **Рабочий режим** — запуск вручную, запуск по расписанию, файл расписания.
6. **Настройки** — таблица из контракта: URL, расписание, лимит, модель. Где хранить ключи.
7. **Формат отчёта** — все поля с пояснениями и пример. Свои имена полей разрешены, только если описаны.
8. **Поведение при сбоях** — недоступный API, повторный запуск.
9. **С чего начинается обработка** — файл точки входа и файл расписания.
10. **Зависимости** и версии.
11. **Проверки** — команда тестов, скрипт оценки и показатели на учебном наборе (от части 3).
12. **Свой сценарий** — кому помогает, какие данные API использует, что выдаёт (от части 4), если он есть.
13. **Вклад участников** — кто что сделал.

## Автоматический прогон тестов

`.github/workflows/tests.yml`: на каждый запрос на слияние — `uv sync` и `uv run pytest`. Модель в тестах не нужна: тесты работают на подставном клиенте.

## Видео — до 3 минут

Задание требует показать три вещи: как сервис получает данные, где применяет ИИ, какой результат выдаёт. Примерная раскладка:

| Время | Что на экране |
|---|---|
| 0:00–0:20 | Задача одной фразой, что будет показано |
| 0:20–1:00 | Рабочий режим: запуск, загрузка двух страниц из API, файл расписания |
| 1:00–1:50 | Где ИИ: одна вакансия, запрос к модели, её ответ, проверка цитаты |
| 1:50–2:30 | Отчёт: понятная вакансия без замечаний, вакансия с противоречием, вакансия с пропусками |
| 2:30–2:50 | Свой сценарий, если есть |
| 2:50–3:00 | Проверочный режим одной командой |

Запишите сценарий в `docs/video.md` до съёмки. Не показывайте в кадре ключи, личные вкладки и переписку.

## Сдача — список перед отправкой

- [ ] Репозиторий публичный, открывается без входа в аккаунт.
- [ ] На чистой машине по README проверочный режим запускается с первого раза.
- [ ] В репозитории и во всей истории коммитов нет ключей и личных данных.
- [ ] `examples/sample_report.json` собран на итоговом коммите.
- [ ] Тесты зелёные на итоговом коммите.
- [ ] Видео короче трёх минут и открывается без входа в аккаунт.
- [ ] SHA итогового коммита записан и отправлен вместе со ссылками.
- [ ] После отправки в отправленный коммит ничего не дописывается: новые правки меняют SHA.
