# Модель, провайдеры и данные

Памятка для того, кто подключает модель (локально или через облачный API). Прочитать до слияния ветки с выбором провайдера.

## Что уходит в модель

В каждом запросе модель получает:
- инструкцию и **методику проверки по семи темам** — ту же, по которой работают правила (`pv/analyze/ai.py`, константа `SYSTEM`);
- поля одной вакансии без контактных данных.

Больше ничего: ни резюме, ни ключей, ни отчётов.

## Локальная модель или облачный API

| | Локальная (Ollama) | Облачный API |
|---|---|---|
| Куда уходят методика и вакансии | никуда, остаются на компьютере | на серверы провайдера |
| Можно ли потом удалить | да, всё лежит локально | нет: отправленное отозвать нельзя, срок хранения определяет провайдер |
| Ключ | не нужен | нужен, хранится только в `.env` |

Правило для ветки с выбором провайдера: **по умолчанию — локальная модель**. Облачный провайдер включается только явной настройкой (`PV_LLM_BASE_URL`, `PV_LLM_API_KEY`), и в README должно быть сказано, что при этом методика и тексты вакансий передаются третьей стороне. У провайдера стоит выбрать режим без хранения запросов и без обучения на них, если он есть.

## Что модель «знает» и чего она не может

- **Сервис не обучает модель.** Веса не меняются. Методика приходит в каждом запросе заново, а «настройка» — это локальный файл профиля (`reports/profiles/`), который решает, каким видам замечаний модели верить.
- **В модели нечего удалять.** Между запросами она ничего не помнит. Удаляется то, что лежит на диске: `python -m pv forget` стирает профили, выученные нормы и кэш.
- **Модель не может узнать, что кто-то нарушил соглашение,** и не может сама что-либо удалить: у неё нет ни сведений о пользователе, ни доступа к файлам. Соблюдение условий обеспечивается документом `LICENSE.md` и подписанными соглашениями, а не моделью.
- **Отказ раскрывать методику** записан в инструкции (пункт 8). Это снижает риск, но не гарантия: небольшую модель можно уговорить. Кроме того, репозиторий публичный, и методика в нём читается напрямую.

## При смене провайдера или модели

- Модель опознаётся по провайдеру и имени. Незнакомая настраивается автоматически (панель) или командой `python -m pv calibrate`.
- После правки `SYSTEM` или правил увеличьте `VERSION` в `pv/analyze/version.py`: старые профили и кэш перестанут применяться.
- Профиль модели по умолчанию поставляется в `pv/profiles/` — после перенастройки его нужно обновить.
