# Часть 3. Качество

Сначала прочитайте `00-contract.md` и `02-analyzer.md`.

## Цель

Дать команде число, по которому видно, стал анализатор лучше или хуже, и набор живых данных, на котором видно, как он ведёт себя вне учебных примеров. Жюри оценивает на закрытом наборе, поэтому наша собственная проверка — единственный способ узнать качество до сдачи.

## Вопросы на старте — решить в первый час и написать в общий чат

**1. Спорные случаи в учебном наборе.** Разметьте и согласуйте с частью 2:
- зарплата только «от» (`salary_max = 0`, вакансия 006) — это замечание или нет;
- одинаковые минимум и максимум (005) — предлагаю не считать замечанием;
- адрес «г. Калининград» без улицы (002, 010) — замечание всегда или только когда об этом сказано в тексте;
- «Образование: не указано» при понятных требованиях (004, 009) — предлагаю не считать: вакансии 009 и 004 иначе перестают быть чистыми.

**2. Что считать совпадением с эталоном.** Предлагаю: совпали вакансия, тема и вид замечания. Текст рекомендации автоматически не сравнивается — его смотрит человек.

## Что должно работать

### Эталон
`eval/gold.json`: для каждой из десяти учебных вакансий — список ожидаемых замечаний с полями `topic`, `kind`, `field` и коротким пояснением, почему это замечание. Для понятных вакансий — пустой список. Отдельно помечайте замечания обязательные и допустимые: допустимое не штрафуется, если найдено, и не штрафуется, если пропущено.

### Скрипт оценки
```
uv run python eval/score.py reports/check.json eval/gold.json
```
Выводит:
- полноту — долю обязательных замечаний эталона, найденных анализатором;
- точность — долю найденных замечаний, которые есть в эталоне (обязательные или допустимые);
- число лишних замечаний на чистых вакансиях — отдельной строкой, это самый важный показатель;
- список расхождений по вакансиям: что пропущено, что лишнее.

Код возврата не ноль, если показатели ниже порогов из `02-analyzer.md`, — чтобы скрипт можно было поставить в автоматическую проверку.

### Живые данные
- `eval/real_sample.json` — 100 вакансий из API в формате ответа API. Контакты (`contact_list`, `contact_person`, `company.email`, телефоны) удалить до того, как файл попадёт в репозиторий.
- Прогнать анализатор, посмотреть глазами 30 случайных вакансий, записать в `eval/review.md`: выдуманные цитаты, замечания не по делу, рекомендации с догадками или с выводами о законе, пропущенные очевидные проблемы.
- Каждую находку — разработчику 2 с ID вакансии.

### Свои примеры
Десять-пятнадцать собственных вакансий в формате учебного набора, с ловушками, которых в учебном наборе нет: расписание только в описании обязанностей, зарплата «по результатам собеседования» при заполненных числовых полях, удалённая работа с адресом офиса, две разные должности в названии и обязанностях. Жюри наверняка заложило похожее.
