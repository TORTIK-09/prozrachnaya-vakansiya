1. Анализ состояния Части 4 в проекте
Проведён аудит существующей реализации относительно спецификации docs/spec/04-extra.md.
Установлено, что в репозитории уже присутствовали:
- модуль своего сценария pv/extra/resume.py (черновик резюме под вакансию на основе данных отчёта);
- вымышленные резюме в examples/sample_resumes.json (RES-01, RES-02, RES-03) и проверка отсутствия выдуманных фактов invented();
- локальная веб-панель (pv/web.py, pv/static/index.html) с безопасной вставкой текста без внешних скриптов и шрифтов;
- базовый набор тестов tests/test_web_extra.py и описание сценария в README.md.

По результатам сверки со спецификацией были выделены четыре пункта доработки и перечень мелких отличий:
1) отсутствие сохранённого примера результата сценария в examples/;
2) поведение кнопок загрузки пользовательского JSON и работы с учебным набором в веб-панели;
3) расширение блока неподтверждённых требований not_confirmed в pv/extra/resume.py (помимо стажа и образования);
4) вопрос подключения клиента модели pv/llm.py в сценарий резюме и мелкие отличия от текста спецификации.

2. Пункт 1 — Сохранённый пример результата сценария (examples/sample_resume_draft.json)
Штатной командой CLI сформирован и сохранён пример результата сценария на тестовых данных (пара RES-03 «Кандидат 3 — аналитика данных» и вакансия DEMO-39-003 «Младший аналитик данных» из examples/sample_report.json, соответствующая примеру команды в README.md).
В examples/sample_resume_draft.json зафиксированы: переупорядоченные по релевантности навыки и пункты опыта, сопроводительное письмо, предупреждение о противоречии в вакансии (опыт 0 против «не менее 5 лет») и вопросы работодателю.
В tests/test_web_extra.py добавлен автотест test_sample_resume_draft_is_fresh_and_has_no_invented_facts, проверяющий актуальность файла относительно текущего кода и выполнение инварианта invented(...) == [].

3. Пункт 2 — Доработка импорта JSON и возврата к учебному набору в веб-панели (pv/web.py, pv/static/index.html)
Проанализирована работа кнопок «Проверить свой JSON…» (/api/check) и «Проверить учебный набор» (/api/check-sample). До исправления загрузка пользовательского JSON полностью затирала учебный набор, а нажатие соседней кнопки запускало повторный разбор всего учебного набора.
Выполнена аккуратная доработка без затрагивания остального функционала:
- в pv/web.py добавлено отдельное сохранение базового отчёта учебного набора в reports/check-sample.json (с автоматическим подхватом, если в reports/check.json уже сохранён учебный набор);
- при импорте пользовательского JSON (/api/check) анализируются только вакансии из загруженного файла (учебный набор не пересчитывается и не перекалибровывается), а результат объединяется с сохранённым учебным набором с сохранением метаданных imported_source и imported_ids;
- при импорте следующего JSON данные предыдущего импортированного файла автоматически удаляются и заменяются новыми поверх того же сохранённого учебного набора без его пересчёта;
- в pv/static/index.html при наличии загруженного JSON кнопка рядом меняет название на «Вернуться к учебному набору», импортированные вакансии помечаются в списке («· из JSON»), а нажатие кнопки (/api/check-sample?restore=1) мгновенно удаляет только данные импортированного JSON и возвращает сохранённый учебный набор без повторного анализа;
- обратная совместимость при отсутствии сохранённого учебного набора (пустая папка reports/) сохранена;
- в tests/test_web_extra.py добавлен тест test_upload_keeps_sample_replaces_prev_json_and_restores_without_reanalysis, покрывающий весь цикл (учебный набор -> первый JSON -> второй JSON -> возврат к учебному набору с нулевым числом повторных вызовов анализатора).

4. Пункты 3, 4 и мелкие отличия — Файл для ревью перед слиянием ветки
В корне проекта создан отдельный временный файл «необходимое к ревью и дорабтки слиянию ветки.txt» с предупреждением в первых строках о том, что после выполнения указанных в нём пунктов файл необходимо удалить.
В файл вынесены:
- Пункт 3: описание доработки not_confirmed в pv/extra/resume.py (учёт текстовых требований из requirements и опыта, указанного только в тексте вакансии; отмечено наличие локальной черновой правки и теста для решения на ревью — принимать, доработать или откатить к коммиту b65490e);
- Пункт 4: вопрос подключения клиента модели pv/llm.py в pv/extra/resume.py и необходимого расширения проверки invented() в случае использования модели;
- мелкие отличия реализации от текста docs/spec/04-extra.md (точка входа CLI pv resume вместо pv.extra, имя файла тестов tests/test_web_extra.py вместо tests/test_extra.py, использование серверной веб-панели вместо автономного web/index.html, отсутствие флага стороннего файла резюме в CLI, упоминание examples/sample_resume_draft.json в README.md).
